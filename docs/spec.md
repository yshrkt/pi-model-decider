# pi-model-decider MVP仕様

本書は、合意したMVP仕様をまとめたものです。Pi 1.2.0を対象とする実装で具体化した上限・既定値と、API上の制約も記載します。

## 目的と位置づけ

Pi Coding Agent向けのExperimentalなExtensionとして、タスクの文脈と自然言語のヒントから、モデルとthinking levelの組み合わせを自動選択する。

選択基準を細かいパラメーターやスコアで設定するのではなく、共通の`selectionHint`と各プロファイルの`hint`で調整する。

classifierは候補の選択だけを担当する。設定検証、候補の絞り込み、応答検証、確認、モデル・thinkingの変更、フォールバックはプログラム側で決定的に処理する。

自然言語による選択は、判断の正確性や最適性を保証しない。classifierの呼び出しと、選択されたモデルの実行には、利用先に応じたAPI使用料金が発生する可能性がある。

## MVPの対象外

- 複雑なスコアリング、信頼度の閾値による選択制御
- コスト計算、予算管理、自動学習
- Subagentオーケストレーション
- 実行中のモデル再評価や自動切り替え
- プロジェクト設定とユーザー設定のマージ
- 汎用チャットLLMを使ったJSON形式の判定バックエンド

## 設定

### 保存先

`~/.pi/agent/extensions/pi-model-decider/config.json`

`~`はユーザーのホームディレクトリに展開する。このExtensionが読む設定ファイルの場所であり、Extension本体のインストール先を規定するものではない。

MVPではこのユーザー設定だけを使用する。

### 設定例

以下の`your-provider`、`your-model`は、利用環境のPiに登録されたモデルに置き換える。classifierも利用環境に登録・認証されている必要がある。

```json
{
  "enabled": false,
  "classifier": {
    "provider": "typesafe",
    "model": "jev-latest",
    "timeoutMs": 5000
  },
  "selectionHint": "現在のプロファイルで十分なら維持する。通常の実装はstandard、複雑な設計や原因調査はdeepを選ぶ。",
  "mode": "selective",
  "profiles": [
    {
      "id": "standard",
      "model": {
        "provider": "your-provider",
        "id": "your-model"
      },
      "thinking": "medium",
      "hint": "通常の実装、修正、質問。",
      "ask": false
    },
    {
      "id": "deep",
      "model": {
        "provider": "your-provider",
        "id": "your-model"
      },
      "thinking": "high",
      "hint": "複雑な設計、原因の分からない不具合、慎重な検討。",
      "ask": true
    }
  ]
}
```

### トップレベルの項目

| 項目            | 型                               | 省略時・意味                                                 |
| --------------- | -------------------------------- | ------------------------------------------------------------ |
| `enabled`       | boolean                          | `false`。自動判定の有効状態                                  |
| `classifier`    | object                           | 使用するPiのclassifierモデル。有効化には指定が必要           |
| `selectionHint` | string                           | 全プロファイルに共通する自然言語の選択方針。省略時は空文字列 |
| `mode`          | `"auto" \| "ask" \| "selective"` | `"ask"`。プロファイル変更時の確認方針                        |
| `profiles`      | array                            | 選択可能なプロファイル。有効化には1件以上必要                |

`default`は設けない。判定に失敗した場合は、現在のモデル・thinkingを維持する。

### classifier

| 項目        | 型     | 意味                                 |
| ----------- | ------ | ------------------------------------ |
| `provider`  | string | Piに登録されたclassifierのprovider   |
| `model`     | string | classifierのモデルID                 |
| `timeoutMs` | number | 判定の待ち時間。省略時は`5000`ミリ秒 |

`timeoutMs`には正の有限整数を指定する。認証や接続先の解決はPiに任せ、設定ファイルに認証情報を保存しない。

### プロファイル

| 項目             | 型      | 意味                                                              |
| ---------------- | ------- | ----------------------------------------------------------------- |
| `id`             | string  | 一意で空でないプロファイルID                                      |
| `model.provider` | string  | 実行モデルのprovider                                              |
| `model.id`       | string  | 実行モデルのモデルID                                              |
| `thinking`       | string  | 対象のPiとモデルがサポートするthinking level                      |
| `hint`           | string  | このプロファイルを選ぶ場面を表す自然言語の説明                    |
| `ask`            | boolean | `selective`でこのプロファイルへの変更を確認するか。省略時は`true` |

モデルとthinkingの組み合わせを1つのプロファイルとして扱う。同一モデルでthinkingが異なるプロファイルは登録可能とする。

同一の`provider + model ID + thinking`の重複登録は認めない。これにより、実際の実行状態から現在のプロファイルを一意に特定する。

## 有効状態とコマンド

| コマンド                | 動作                                                   |
| ----------------------- | ------------------------------------------------------ |
| `/model-decider on`     | 設定の`enabled`を`true`に保存し、自動判定を有効化する  |
| `/model-decider off`    | 設定の`enabled`を`false`に保存し、自動判定を無効化する |
| `/model-decider status` | 有効状態、現在のプロファイル、直近の判定結果を表示する |

on/offはセッション内だけの一時設定にはせず、設定ファイルに反映する。

保存は以下の順序で行う。

1. 設定ファイルを読み直し、JSONとして検証する。
2. 他の項目を保持し、`enabled`だけを変更する。
3. 同じディレクトリの一時ファイルに書き込み、置き換える。
4. 保存に成功した後、実行中の有効状態を変更する。

保存失敗時は実行中の有効状態を変更せず、エラーを通知する。不正なJSONは上書きしない。JSONの値は保持するが、整形の維持は保証しない。

オフにしても現在のモデル・thinkingは戻さない。以降のclassifier呼び出しを止める。既に進行中の判定がある場合、その結果によって無効化後に切り替わらないようにする。

`status`はclassifierを呼び出さない。

## 判定タイミング

ユーザーの依頼開始時に1回判定し、確認・適用後はその依頼の実行中、選択したプロファイルを固定する。ユーザーが「Reselect」を操作した場合だけ、追加の判定を行う。

通常のツール実行、ツール結果、実行の継続、再試行を理由とする再判定は行わない。実行中に届いたsteeringによる再判定も行わない。

この制限により、頻繁な切り替えとclassifier呼び出しを抑える。キャッシュ効率の改善や保持を保証するものではなく、同一モデルのthinking変更についてもキャッシュ維持を仮定しない。

Piでユーザーが手動変更したモデル・thinkingを現在値として尊重する。次の依頼では、その状態をもとに通常どおり自動判定する。

## 現在のプロファイル

現在の実際の`provider + model ID + thinking`と一致するプロファイルを現在のプロファイルとする。

設定外の組み合わせを利用中の場合、現在のプロファイルIDは`null`とする。その場合も実際のモデル・thinkingを保持し、判定入力に含める。

起動時や有効化時に、いずれかのプロファイルへ無条件に切り替えることはしない。

## 判定入力とclassifier接続

Piに登録されたclassifierモデルを、Piの公開Registry経由で呼び出す。classifier呼び出し部分は、テストでモック可能なアダプターとして分離する。

判定入力に含める情報は以下とする。

- 現在の依頼
- 現在のプロファイルIDと、実際のモデル・thinking
- 共通の`selectionHint`
- 選択可能な各プロファイルのID、モデル、thinking、`hint`
- 現在のセッションブランチの直近会話と、必要なツール実行履歴

有効なプロファイルを選択肢とする、単一のchoice質問を使用する。共通方針は質問の指示に、各プロファイルのhintは選択肢の説明に対応させる。

履歴と依頼を含む判定入力には上限を設け、古い履歴から削る。欠落がある場合はその事実を判定入力に明記する。思考本文、画像本体、システムプロンプトは送らない。実装ではJSONシリアライズ後の全体上限を32,000文字とする。依頼は最大12,000文字、履歴は直近12メッセージからテキストを各最大2,000文字・合計最大12,000文字まで抽出する。ツール結果はツール名・エラーフラグ・テキストだけを含める。全体が上限を超える場合は履歴、次に依頼を削る。方針と候補だけで上限を超える場合は失敗扱いにする。

依頼やツール結果は判定対象のデータとして扱い、設定方針や許可候補を変更する指示として扱わない。プログラム側の候補制限・検証を最終的な制約とする。

選択に必要な会話内容がclassifierの利用先へ送られる可能性をREADMEに明記する。

## 応答検証と選択

有効候補が1件の場合はclassifierを呼ばず、その候補を通常の確認フローへ渡す。2件以上の場合、classifierが返す確率分布などの構造化応答を検証し、有効な候補の中で最大確率のプロファイルIDを選ぶ。信頼度の閾値は設けない。

同率の場合は次の順序で決定する。

1. 現在のプロファイルが同率候補にあれば、それを優先する。
2. それ以外は設定ファイルのプロファイル順を優先する。

正常終了していない応答、不正な分布、候補外ID、不正な数値、必要な回答の欠落などは失敗扱いとする。利用するclassifier APIの契約に沿った具体的な検証を実装する。

タイムアウトの既定値は5秒とし、自動リトライや不正応答の修復用再問い合わせは行わない。ユーザーの再選択ごとに、新しい判定の待ち時間を適用する。

classifierは設定の変更、確認の省略、任意モデルの追加、モデルの直接切り替えを行えない。

## 確認フロー

提案が現在と同じプロファイルの場合、確認も変更も行わず続行する。

| `mode`      | プロファイル変更時の確認            |
| ----------- | ----------------------------------- |
| `auto`      | すべて自動承認                      |
| `ask`       | すべて確認                          |
| `selective` | 切り替え先プロファイルの`ask`に従う |

同一モデルのthinkingだけの変更にも、同じ確認ルールを適用する。

確認UIには、現在と提案先のプロファイル・モデル・thinkingを示し、以下の操作を英語表記で提供する。

- **Approve（承認）**：提案先へ切り替えて続行する。
- **Reject（拒否）**：現在のモデル・thinkingを維持して続行する。
- **Reselect（再選択）**：提案済みの候補を除外し、classifierを再実行する。

ダイアログを閉じた場合や、確認が必要なのにUIを利用できない場合は、拒否として扱う。依頼自体の中止とは区別する。

### 再選択

除外集合は今回の依頼に限って保持する。再選択時には、今回の提案先と、それ以前に再選択で退けたプロファイルをすべて除外する。

除外後の有効候補が2件以上ある場合だけ「Reselect」を表示する。候補が1件だけの場合に、その候補を自動適用する動作は行わない。

現在のプロファイルは、提案先として除外されていない限り、維持を選べる候補として残す。再判定で現在のプロファイルが選ばれた場合は、そのまま続行する。

別のプロファイルが再提案された場合は、新しい切り替え先について確認ルールを改めて適用する。除外済みIDが返った場合は不正応答として扱う。

拒否は現在を維持して今回の確認フローを終了する。次の依頼では除外集合をリセットし、全プロファイルを再び候補に戻す。

## 設定検証と候補の利用可能性

設定構造の不正と、実行時の利用不能を分けて扱う。

### 設定構造の不正

ID重複、組み合わせの重複、型の不正、不正な`mode`やthinking値、不正なタイムアウト値などは設定エラーとする。自動判定を無効にし、原因を通知する。現在のモデル・thinkingは変更しない。

設定ファイルがない場合も、設定なしとして自動判定を行わない。ファイル未作成時のコマンドによる初期化や、不足項目の入力支援はMVPでは行わない。

### 実行時の利用不能

以下に該当するプロファイルは候補から除外し、原因を通知する。

- モデルがPiに登録されていない。
- 必要な認証が設定されていない。
- 指定されたthinkingをモデルがサポートしていない。
- 必要な画像入力など、依頼で使用する入力形式をモデルがサポートしていない。

Piによるthinkingの暗黙の補正を前提にせず、指定した組み合わせが成立することを確認する。

利用可能な候補がない場合、classifierを呼び出さず現在を維持する。classifier自体が利用不能な場合も同様とする。

## 適用とフォールバック

モデルとthinkingは一体のプロファイルとして扱うが、Piへの適用は順序を管理する。

1. 変更直前の実際のモデル・thinkingを保持する。
2. 提案先の利用可能性を再確認する。
3. モデルが異なる場合はモデル変更を実行し、成功を確認する。
4. thinkingを設定し、実際の適用値を確認する。
5. 成功した状態を現在値として扱う。

| 状況                                       | 動作                                                     |
| ------------------------------------------ | -------------------------------------------------------- |
| 判定エラー、タイムアウト、不正応答         | 現在を維持して続行                                       |
| 拒否、確認UIなし、確認キャンセル           | 現在を維持して続行                                       |
| 提案先が適用前に利用不能になった           | 現在を維持して通知                                       |
| 変更途中の失敗、thinkingの不一致           | 元の状態へ復元を試み、通知                               |
| 復元不能、または現在のモデル自体が利用不能 | 任意の別モデルへ退避せず、エラーを通知して実行を止める   |
| 依頼自体の中止                             | 判定・確認を中止し、フォールバックによる実行を開始しない |

on/off、手動変更、セッション切り替え、ブランチ移動、reload、終了などによって前提が変わった後に、古い判定結果や確認結果を適用しない。新しいセッションの状態を古い処理から変更しない。

## 判定ログ

`~/.pi/agent/extensions/pi-model-decider/logs/pi-model-decider-decisions.jsonl`へJSONL形式で追記する。`pi-permission-system`に合わせて、共通メタデータとして`timestamp`、`extension`、`stream`、`event`、`sessionId`を持つ。

自動判定が有効なユーザー依頼について、選択・確認フローの終了時に1行記録する。本処理のモデル実行結果を記録するものではない。無効状態、カスタムメッセージ、statusコマンドでは出力しない。

| フィールド                       | 内容                                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| `timestamp` / `startedAt`        | 完了時刻・開始時刻（UTC ISO 8601）                                                           |
| `extension` / `stream` / `event` | `pi-model-decider` / `decisions` / `decision_completed`                                      |
| `sessionId` / `requestId`        | 元のPiセッションID・依頼ごとのUUID                                                           |
| `instruction`                    | 現在のユーザー指示全文（Piによる展開後のテキスト）                                           |
| `classifier` / `mode`            | 判定に使ったclassifierの参照・期限と確認モード                                               |
| `current`                        | 判定開始時のプロファイルID・モデル・thinking                                                 |
| `proposedProfile`                | 最後の試行で検証済みの提案先ID・モデル・thinking。提案なしは`null`                           |
| `probabilities`                  | 最後の試行の検証済み確率分布。失敗・未実行時は`null`                                         |
| `durationMs`                     | 確認待ちを含む選択フロー全体の時間（ログ書き込みと本処理は含まない）                         |
| `classifierDurationMs`           | classifierの各試行時間の合計。入力作成・検証を含み、確認待ちは含まない                       |
| `attempts`                       | 再選択を含む各試行の候補ID、提案先、確率、判定時間、確認操作、判定エラー                     |
| `result`                         | 最終結果（`applied`、`unchanged`、`rejected`、`failed`、`cancelled`、`fatal`）と関連ID・理由 |
| `finalSelection`                 | 選択フロー終了時のモデル・thinking・プロファイルID。セッションの置き換え後は`null`           |

`attempts[].source`でclassifierによる選択と単独候補の選択を区別する。未実行時に確率を捏造しない。不正な応答は確率・提案先として保存せず、エラーだけを記録する。遅れて返る無効な結果を追記しない。

ログディレクトリは必要に応じて作成する。新規ディレクトリは`0700`、新規ファイルは`0600`で作成し、同一Extension内の追記を直列化する。ローテーション・自動削除は行わない。

ユーザー指示は全文を保存する。会話履歴・認証情報・classifierの生応答は保存しない。ログ保存に失敗しても判定やモデル変更を失敗扱いにせず、セッションにつき一度警告する。次回以降の書き込みは再び試みる。statusコマンドにもログの場所を表示する。

## Pi APIと実装構成

調査時のローカルPiは`1.2.0`。実装時には対象バージョンの公開API・型定義・挙動を改めて確認し、対応バージョンを明記する。

| 用途                 | API・イベント候補                                             |
| -------------------- | ------------------------------------------------------------- |
| classifierの解決     | `ctx.modelRegistry.findOfType("classifier", provider, model)` |
| classifierの呼び出し | `ctx.modelRegistry.classify(...)`                             |
| 実行モデルの解決     | `ctx.modelRegistry.find(provider, modelId)`                   |
| モデルの変更         | `await pi.setModel(model)`                                    |
| thinkingの取得・変更 | `pi.getThinkingLevel()` / `pi.setThinkingLevel(level)`        |
| 確認UI               | `ctx.ui.select(...)`                                          |
| UIの有無             | `ctx.hasUI`                                                   |
| 依頼開始時の判定     | ユーザーメッセージを起点とする`before_agent_start`            |
| 会話文脈の取得       | `ctx.sessionManager.buildSessionContext()`                    |

`setModel()`の失敗戻り値と、`setThinkingLevel()`の補正挙動を考慮する。Extensionによる切り替えは、Piのグローバルなモデル・thinkingの既定値を変更しない。

設定の読み書き・検証、文脈作成、classifierアダプター、応答検証、確認フロー、Piへの適用を分離する。classifierとPi操作をモックし、外部API料金なしでテスト可能にする。

### Pi 1.2の中止通知に関する制約

`before_agent_start`中はrunの`AbortSignal`が存在しない場合がある。TUIでは判定待ち中のEsc/Ctrl+Cを監視して補うが、RPCからのabortはこの段階でExtensionに通知されない場合がある。この場合は期限または応答を待つことになり、実行中止済みでもモデル選択が反映される可能性がある。依頼の実行中止自体はPiが処理する。完全な開始前キャンセルの保証は、この通知が公開APIで利用できるPiバージョンへの対応が必要になる。

## 検証項目

- 設定の既定値、型検証、ID・組み合わせ重複、設定未作成・不正JSON
- classifierのprovider・model解決と、接続アダプターの差し替え
- 候補の利用可能性、非対応thinking・入力形式の除外
- 選択結果、同率時の優先順、設定外の現在値
- 3種類のmodeと、プロファイルの`ask`省略時の`true`
- 同一モデルでthinkingだけを変更する場合の確認
- 承認、拒否、確認キャンセル、UIなし
- 再選択の除外集合と、残り候補数が0・1・2件の境界
- 再選択後の確認ルールと、除外済み候補の不正な再提案
- classifierの異常応答、異常終了、エラー、5秒の既定期限と設定した期限
- タイムアウト後に遅れて返る結果を適用しないこと、自動リトライしないこと
- 依頼につき1回の判定と、実行中に再判定しないこと
- モデル変更失敗、thinking不一致、復元、復元不能
- on/offの永続化、他項目の保持、保存失敗時の実行状態維持
- 無効化、手動変更、セッション変更、中止後に古い結果を適用しないこと
- `status`と無効状態でclassifierを呼ばないこと

純粋なロジックのテストに加え、対象PiでExtensionの読み込み、判定タイミング、UI、モデル・thinking切り替えを確認する。実モデルを使う検証は、モックテストと区別する。

ログについては、実ファイルへの追記、改行を含む指示、ファイル権限、再選択の全試行、確率未取得時の`null`、キャンセル後の遅延応答、保存失敗時の継続も検証する。
